# 轻量化与白话体验改造任务清单

这份清单用于跟踪本轮开发。目标是让小改动走短路径，让高风险改动仍保留完整检查，同时让普通用户不必先学习内部协议术语。

状态说明：

- `计划中`：范围已经确定，尚无实现证据。
- `进行中`：已经开始修改，但验收证据还不完整。
- `已完成`：实现、自动检查和实际生成结果都能证明该项成立。

> 清单中的状态不能仅凭代码已修改而改成“已完成”。负责人应在最终验收后补齐“完成证据”，再更新状态。

## 3. 缩短低风险改动循环

### 开发项

- [x] 轻量处理采用：确认范围 → 一次批量修改 → 针对性检查 → 汇总结果。
- [x] 首次检查失败后最多进行两次修复；仍失败时给出具体失败原因和可继续的选择。
- [x] 在最终检查之前先审阅改动差异，避免检查通过后又因审阅修改而重复全套验证。
- [x] 低风险改动只运行与改动直接相关的检查；发布前或风险升级后再运行完整检查。
- [x] 过程状态、完成标准和交付记录在一轮结束时统一写入一次，避免每一步重复同步。
- [x] 不为维持循环而调用无价值工具；已确认且未变化的上下文不重复读取。

### 验收证据

- [x] 测试证明修复次数存在上限，且边界没有多一次或少一次。
- [x] 测试证明执行顺序为“审阅改动 → 最终检查”。
- [x] 测试证明同一轮低风险交付最多发生一次汇总记录写入。
- [x] 代表性小改动的执行轨迹不再创建不必要的完整需求文件夹或重复检查。

## 最终验收记录

完成开发后，由主任务负责人填写：

- 实现提交或变更范围：policy 解析器、初始化器、core 命令/模板/能力、多工具入口、README/安装文档、回归测试与发布准备信息。
- 自动检查命令与结果：`npm run check` 通过；`git diff --check` 通过；最终 1.1.0 发布包与 manifest 均包含 119 个文件条目。
- 临时工作区生成结果：7 类工具入口生成成功；Codex 为 1 个总入口 + 32 个阶段 Skill；`AGENTS.md` 2,791 bytes。
- 轻量处理演示：`src/ui/button.ts` 解析为 `adaptive`（“自动选择”），无升级条件；阶段读取链不再回读 `AGENTS.md` 或完整 manifest。
- 完整检查演示：`db/migrate/20260820_add_users.rb` 解析为 `strict`，原因为数据迁移；`pre_merge_or_release` 也解析为 `strict`。
- 旧工作区兼容演示：可识别的旧工作区无 policy 时，普通重跑和 `--upgrade --force` 均生成 `strict`；真正的空目录即使带 `--upgrade` 仍为 `adaptive`；已有自定义 policy 完整保留。
- 默认话术人工走查：README、完成标准指南、进度/完成标准模板、主视觉和生成入口均以白话为主；内部名称只留在高级兼容信息或 HTML 注释。
- 未完成项或已知限制：这份清单记录 1.1.0 的开发验收；版本是否已经公开发布，以 npm Registry、不可变 Git Tag 和 GitHub Release 的公开结果为准。policy 判定由解析器确定性执行；具体修改循环仍由接入该 kit 的 agent 遵循。
