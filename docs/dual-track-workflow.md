# 双轨工作流设计：研发轨 + 商业化轨

本文说明 OpenOne Workflow Kit 的双轨工作流：研发轨（features）负责把需求做出来并发布，商业化轨（business）负责回答"卖给谁、怎么卖、在哪卖、花多少钱、卖得怎么样"。两轨共享同一套授权口径，面向没有市场团队的个人开发者。

## 为什么是双轨而不是加长研发流程

- 作用域不同：研发轨以"需求"为单位（每个 feature 一轮生命周期）；商业化轨以"产品"为单位（一份长期维护的基线 + 周期性复盘），把 B 阶段塞进每个需求会重复且错位。
- 节奏不同：研发阶段是顺序推进后归档；定位、渠道和预算是持续修订的活文档，B9 复盘按周期循环。
- 授权边界不同：研发轨的危险动作是 push/部署/数据库写入；商业化轨的危险动作是对外发布、投放花钱和 cold outreach，需要单独口径。

## 总览

```
商业化轨（每产品一份基线，business/{product}/）
  /new-product
     └─ /B1-业务定位 ─ /B2-商业模式 ─ /B3-PMF与客户画像 ─ /B4-场景与购买旅程
        ─ /B5-渠道漏斗映射 ─ /B6-营销获客策略 ─ /B7-营销预算 ─ /B8-渠道执行策略
        （首次可用 /B1-B8-商业化准备 一次性串联；关键决策点需用户确认）
                 │ 提供输入                                  ▲ 数据与信号回流
                 ▼                                          │
研发轨（每需求一轮，features/{feature}/）                     │
  /new-feature ─ /01 ─ /02 ─ /02B ─ /03 ─ /04 ─ /05 ─ /06 ─ /07 ─ /08 ─ /09 ─ /10
                                                             │
增长循环（上线后按周期）                                       │
  渠道执行（用户授权后）→ 数据采集 → /B9-策略复盘 ──────────────┘
     ├─ 常规偏差：修订 B5-B8（渠道/策略/预算/打法）
     └─ 重大失配：上溯修订 B1/B2/B3（定位/模式/画像）
```

## 商业化轨九个阶段

| 阶段 | 回答的问题 | 关键产出 |
| --- | --- | --- |
| `/B1-业务定位` | 我是谁、和谁竞争、凭什么赢 | 产品服务盘点、市场调研、竞品矩阵、可证伪的定位陈述、细分取舍 |
| `/B2-商业模式` | 钱从哪来、成本去哪、账算不算得过来 | 精益画布、收入模式与定价假设、单位经济、CAC 上限、关键假设清单 |
| `/B3-PMF与客户画像` | 有没有人真的要、理想客户是谁、谁不服务 | PMF 信号定义与判定、验证实验记录、ICP、负面画像 |
| `/B4-场景与购买旅程` | 用户在什么场景用、怎么走到付费 | JTBD 场景清单与优先级、认知到推荐的旅程表、异议清单、材料缺口 |
| `/B5-渠道漏斗映射` | 每个渠道在漏斗哪一层、起什么作用 | 漏斗口径、offline/online 渠道评估表、渠道-漏斗矩阵、主攻候选 |
| `/B6-营销获客策略` | 总体打法是什么 | 阶段判断、目标体系、主攻渠道组合、信息一致性、内容支柱、发布节奏 |
| `/B7-营销预算` | 花多少钱、投多少时间、何时止损 | 金钱+时间双预算表、各渠道上限与止损线、CAC 目标 |
| `/B8-渠道执行策略` | 每个渠道具体怎么干 | SEO playbook（关键词/内容日历/技术清单）、各渠道 playbook、实验设计、营销工程需求清单、待授权动作清单 |
| `/B9-策略复盘` | 打得怎么样、下周期怎么调 | 数据快照、假设判定、渠道加码/保持/降配/砍掉决策、上溯修订、下一周期计划 |

线下渠道示例：events / conferences、local meetups、hackathons、线下工作坊。线上渠道示例：paid ads、SEO、cold outreach、influencer marketing、social media、email marketing、partnership、开发者社区、应用与插件市场、目录站、开源仓库分发。

## 两轨衔接点

| 衔接点 | 方向 | 规则 |
| --- | --- | --- |
| 需求入口 | B → 研发 | `/01-需求讨论`、`/02-产品文档` 读取 B1/B2/B3/B4：需求价值挂到 ICP 与场景；命中负面画像的需求显式标记待用户确认；付费相关需求与 B2 口径一致 |
| 发布材料 | B → 研发 | `/08-发布准备` 对照 B5/B8 渠道计划补齐发布营销材料（landing 更新、SEO 元数据、商店文案、发布帖与邮件草稿） |
| 发布分发 | 研发 → B | `/09-发布执行` 完成后按 B8 生成本次发布的渠道分发清单，逐项等待用户授权或自行执行 |
| 营销工程回流 | B → 研发 | B8 中的 landing page、博客/文档站、埋点、A/B 测试、分享机制通过 `/new-feature` 进入研发轨，遵守全部研发闸门 |
| 复盘闭环 | 双向 | `/10-复盘总结` 记录增长信号回流 `/B9-策略复盘`；B9 的渠道经验沉淀回知识库；重大失配上溯 B1/B2/B3 |

商业化基线缺失时研发轨不阻塞，只记录缺口——已有项目可以先跑研发轨，随后补 `/new-product`。

## 授权与证据边界

- B 阶段只产出文档和清单。对外动作——发布内容、投放广告、发送 cold email、联系 influencer/合作伙伴、提交目录站——必须用户明确授权或自行执行；付费投放支出 `paid_ad_spend: manual-only`。
- 市场结论必须证据分级：一手（访谈、自有数据）/二手（公开来源，注明来源与日期）/推断（标注验证方式）。不得编造市场规模、用户评价、竞品价格；能力见 `workflow/core/capabilities/market-evidence-grader.md`。
- 每个渠道当实验管理：事前定义假设、双预算上限、周期与判定标准；能力见 `workflow/core/capabilities/channel-experiment-tracker.md`。
- cold outreach 与 email marketing 遵守目标市场反垃圾邮件与隐私法规（如 CAN-SPAM、GDPR）及平台规则；联系人名单存本地未跟踪文件，文档只记录路径。
- 未达 PMF 信号前，投放保持最小实验档；个人开发者同时主攻渠道默认不超过 2-3 个，时间预算与金钱预算同等约束。

## 节奏建议

| 频率 | 动作 |
| --- | --- |
| 一次性（每产品） | `/new-product` → `/B1-B8-商业化准备`（关键决策点用户确认：定位、定价、ICP、主攻渠道、预算） |
| 每个需求 | 研发轨 `/new-feature` → `/01` … `/10`，入口和发布阶段消费商业化基线 |
| 每周 | 检视漏斗与渠道指标（B9 的数据输入，不必产出完整复盘） |
| 每月 | `/B9-策略复盘`：渠道处置决策、预算调整、修订 B5-B8 |
| 每季度 | B9 扩展为定位校准：重检 B1/B2/B3 是否仍然成立 |

## 典型旅程：一个新产品从 0 到 1

1. `/new-product my-tool` 建容器；`/B1-B8-商业化准备` 产出定位、模式、ICP、旅程、渠道、策略、预算、playbook 基线。
2. `/new-feature mvp` 走研发轨 01→07；`/08-发布准备` 时对照 B8 补 landing 文案与 SEO 元数据；`/09-发布执行` 获授权后发布，并生成 Product Hunt/社区/邮件分发清单等待用户执行。
3. B8 回流的 `/new-feature landing-page`、`/new-feature analytics-events` 各走一轮研发轨。
4. 上线四周后 `/B9-策略复盘`：SEO 早期信号保持、某社区渠道 CAC 超标降配、发现 ICP 偏差 → 修订 B3 并回流 `/01` 调整下一轮需求优先级。
5. `/10-复盘总结` 沉淀发布经验，增长信号写入下轮 B9 输入。

## 落点与文件

- 商业化容器：工作区级 `business/{product}/`，状态文件 `00-商业化状态.md`（模板 `workflow/core/templates/00-business-status.md`），素材放 `business/{product}/素材/`。
- 阶段文档模板：`workflow/core/templates/business-stage-document.md`。
- 阶段契约：`workflow/core/commands/new-product.md`、`B1-业务定位.md` … `B9-策略复盘.md`、`B1-B8-商业化准备.md`。
- 配置：`workflow/team-profile.yaml` 的 `workflow.business_dir`、`risk_policy.outbound_marketing_actions`、`risk_policy.paid_ad_spend`、`source_materials.market_research`。
