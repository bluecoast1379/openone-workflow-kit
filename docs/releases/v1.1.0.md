# OpenOne Workflow Kit v1.1.0

This release makes the workflow proportional to the risk of the requested change. Small local edits take a short, bounded path, while API, data, authorization, migration, production, and release work still receive full checks.

## Highlights

- New installations receive a managed `workflow/policy.yaml` and default to automatic selection. Existing workspaces without a policy retain full checks during upgrade.
- A low-risk local change can proceed directly from the user's implementation request, without creating a feature folder or waiting for a second confirmation.
- Lightweight delivery is bounded to two repair cycles, reviews the complete diff before final targeted verification, and writes one end-of-run record.
- Generated `AGENTS.md` is 2,791 bytes, and the comparable fixed stage read chain is 54.2% smaller than before.
- Codex receives one plain-language umbrella Skill and 32 compatible stage Skills. Claude, Cursor, Copilot, CodeBuddy, Kiro, and Trae use the same user-facing titles.
- Default wording now uses completion standard, acceptance item, check result, and explicit blocker. Legacy command IDs, Skill slugs, file names, and completion-contract formats remain compatible.
- `openone-workflow-resolve-policy` provides deterministic policy validation and risk escalation, with regression coverage for common migration, authentication, CI/CD, deployment, and production-config paths.

## Install

Requires Node.js 18 or newer.

```bash
npm install --save-dev openone-workflow-kit@1.1.0
npx openone-workflow-init --target . --tools codex,claude,cursor --yes
```

You can then describe a small local change directly. The generated agent instructions choose the lightweight path when the scope is clear and automatically switch to full checks when a declared risk condition is present.

## Upgrade from an earlier version

Preview the managed-file update first:

```bash
npx --yes --package openone-workflow-kit@1.1.0 openone-workflow-init \
  --target . --tools codex --upgrade --force --dry-run
```

Then apply it:

```bash
npx --yes --package openone-workflow-kit@1.1.0 openone-workflow-init \
  --target . --tools codex --upgrade --force --yes
```

An identifiable older workspace without `workflow/policy.yaml` receives a policy whose default is full checks. A truly new workspace defaults to automatic selection. Existing policy files and user-owned adapter files are preserved.

## Safety boundary

Automatic selection does not authorize remote pushes, releases, deployments, database writes, production changes, paid actions, or external contact. Those actions still require explicit user authorization. Missing policy files fail closed to full checks, and only checks that actually ran may be reported as passed.
