# 工作区协作说明

OpenOne 会根据改动风险选择工作量：范围清楚、可恢复的小改动直接轻量处理，风险升高时自动改用完整检查。普通任务直接描述目标即可，不必先学习阶段编号。

## 接到任务时

1. 读取 `workflow/policy.yaml`；文件缺失时采用“完整检查”。
2. 读取 `workflow/team-profile.yaml`，确认项目位置和本地操作范围。
3. 只读取与当前任务对应的一份 `workflow/core/commands/<阶段>.md`，以及直接相关的代码和资料。
4. 用户已经要求修复、修改或实现本地内容时，可在其范围内直接开始，不重复索要同一确认。

## 处理方式

- “自动选择”是新安装默认方式。低风险任务按“确认范围 → 批量修改 → 审阅完整改动 → 最终定向检查 → 一次汇总”完成，最多修复两轮。
- 涉及对外接口、数据结构、权限、安全、迁移、持续集成与部署流程（CI/CD）、生产配置、跨项目改动、不可逆操作，或改动超出原范围时，采用“完整检查”。
- 合并或正式发布前采用完整检查。

## 始终遵守

- 只报告真实执行过的检查；无法验证时说明原因和剩余风险。
- 修改前检查未提交内容，保留用户已有改动，不扩大任务范围。
- 远程推送、发布、部署、数据库写入、生产配置写入、公开发布、投放、对外联系以及破坏性操作，必须先得到用户明确授权。
- 同一项目确有并行修改时，使用彼此隔离的开发目录。
- 用户要求查看、解释或审查时保持只读；用户要求修改或开发时才实施本地变更。

## 默认表达

优先使用“这次改动、完成标准、验收项、检查结果、明确卡点、需要你确认”。内部编号和英文状态仅在技术详情中展示。

按需查找项目原则 `workflow/constitution.md`、已上线行为 `specs/`、改动资料 `features/` 和商业规划 `business/`。旧阶段编号可在 `workflow/core/command-manifest.yaml` 中查询。
