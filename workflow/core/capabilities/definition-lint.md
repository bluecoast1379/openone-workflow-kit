# 完成标准检查

## Purpose

在完整检查模式中，确认完成标准之前检查是否足以指导实现与验收。轻量处理不运行本检查；不应把它变成小改的隐性必填表。

## 八项检查

| # | 检查内容 | 通过标准 |
| --- | --- | --- |
| 1 | 数据来源、去向和状态变化 | 说清唯一权威来源、关键状态和必须始终成立的约束 |
| 2 | 出错时的处理和恢复 | 覆盖超时重试、重复请求、并发冲突、中途退出、配额、非法输入和依赖故障；不适用项有理由 |
| 3 | 质量限制 | 性能、资源、成本、依赖和安全有硬数字，或明确说明无约束的理由 |
| 4 | 验收方法可重复 | 每个目标至少有一个验收项；每项有命令或明确的人工步骤；至少一项必须通过 |
| 5 | 模糊词已精确说明 | “快/流畅/稳定/好用”等词都绑定数字或可观察行为；无未解决待确认项 |
| 6 | UI 体验底线 | 有 UI 时明确空/错/载状态、感知性能、可访问性，并有一项人工体验验收；纯后端可说明不适用 |
| 7 | 业务指标关联 | 存在商业基线时说明预期影响的指标；无基线时记录缺口而不编造 |
| 8 | 改动范围 | 允许改和禁止改的部分清楚，对外 API/数据结构/事件已对照当前行为 |

## 按项目类型追问

只选择当前项目相关的问题，答案必须回写到完成标准，不留在对话中。

- 通用：最大输入、重复执行、中途中断、不可恢复数据、单用户/单请求成本上限。
- Web/API：弱网与超时、并发写入、认证失效、P95 延迟与首屏条件。
- CLI：CI/管道中的行为、退出码、中断残留、破坏性操作的预览和确认。
- 浏览器扩展：页面结构变化后降级、最小权限、存储配额和同步冲突。
- 移动应用：离线/弱网、进程被杀后恢复、权限被拒、冷启动和包体。
- Agent 服务：重复调用、部分成功、上游超时/限流、长任务进度与取消。
- 静态站点：构建失败或数据源缺失、SEO 元数据和结构化数据。

## Rules

- 每一项记为“已通过 / 未通过+缺口 / 已确认跳过+风险”。
- 例外必须由用户明确确认；agent 不得自行豁免。
- 不得在仍有未解决待确认项时标记通过。
- 不得把“尽量快”等愿望当作可检查限制。

## 内部兼容详情

文件名 `definition-lint.md` 和机器字段 `Definition Lint`、`Oracle`、`blocking`、`manual/auto` 为兼容保留；默认用户输出使用“完成标准检查/验收项/必须通过/人工/自动”。
