# /04A-前端代码实现

## Goal

完成范围内的页面、组件、状态、接口衔接和前端验证。

## Required Inputs

- `/04-代码实现` 的处理方式与开始条件结果
- 用户请求、现有 UI、前端规范和本地代码
- 完整检查或新 UI 方案时：`features/{feature}/02B-UI设计.md`

## Execution Rules

- 继承 `/04-代码实现` 的策略解析、分支与未提交改动检查、自动升级条件、证据真实性和远程写入授权边界。
- **轻量 UI 规则**：仅文案、既有页面局部样式、既有组件内的明确交互修正，可以用用户请求、现有 UI 和现有前端规范作为基准，**无需单独的 `02B-UI设计.md` 或豁免确认**。
- 新增页面、新用户流程、跨页状态、设计系统变更，或现有 UI 无法明确推导方案时，不再属于低风险 UI 小改：升级为完整检查并先补齐 `/02B-UI设计`。
- 存在 `02B-UI设计.md` 时，实现应遵循其信息架构、关键流程、页面清单、组件规范、平台适配、可访问性和视觉验收要求。有意偏离需记录原因、影响页面、风险和后续处理人。
- 可运行应用或原型存在时，按已确认的设备、视口和状态范围保留截图或等价的视觉证据。
- 发现改动超出已确认范围时，不得静默扩大。

## Required Outputs

- 轻量处理：最终一次性记录修改的页面/组件、diff 审查和验证证据。
- 完整检查：更新 `features/{feature}/04A-前端代码实现.md` 与状态文件。
- 明确列出仍需人工观察的屏幕、状态和设备。
