# /05-代码审查

## Goal

审查完整 diff：先找正确性、越界、回归和发布风险，再总结改动。

## Required Inputs

- 真实完整 diff、当前分支和未提交改动
- 轻量处理：用户请求与已确认范围
- 完整检查：完成标准、产品说明、技术方案、项目基本规则和代码规范

## Execution Rules

- 按严重程度列出具体问题，引用文件、diff、测试或运行证据。没有问题时明确说“未发现问题”，不为了产出而编造。
- 检查 diff 是否超出“这次会改什么”，是否触碰禁止范围，是否覆盖无关用户改动。
- 轻量处理中发现对外 API/数据结构、认证权限、迁移、持续集成与部署流程（CI/CD）、生产配置、跨仓、不可逆操作或改动超出范围，标记对应升级条件并转为完整检查。
- 完整检查中，对照完成标准、产品意图、项目基本规则和代码规范。验收标准、阈值或“必须通过”标记有未记录修订时，按高风险问题上报。
- 审查必须在最终验证之前完成。审查导致代码修改时，重新审查完整 diff，然后才运行最终验证。
- 本命令本身只读；修复需回到实现命令。

## Required Outputs

- 问题清单（严重度、位置、影响、建议修复）。
- 轻量处理：将最终审查结论放入终点摘要，不单独创建过程文档。
- 完整检查：更新 `features/{feature}/05-代码审查.md` 和状态文件。
