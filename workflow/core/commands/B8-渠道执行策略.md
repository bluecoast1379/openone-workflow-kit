# /B8-渠道执行策略

## Goal

渠道执行策略: 为 B6 选中的渠道制定可执行 playbook——SEO 关键词与内容日历、各渠道动作节奏与判定标准——并把营销工程需求回流研发轨。

## Required Inputs

- `workflow/team-profile.yaml`
- Workspace-level `business/{product}/B4-场景与购买旅程.md`（材料缺口）、`B5-渠道漏斗映射.md`、`B6-营销获客策略.md`、`B7-营销预算.md`
- 关键词与流量数据、平台规则文档（如可获取）

## Execution Rules

- Read local facts before writing conclusions.
- 只为 `/B6-营销获客策略` 选中的主攻和实验渠道写 playbook，未选中渠道不展开。
- SEO 结论（关键词选择、页面结构）必须有搜索数据或竞品页面证据支撑；拿不到数据时标注为假设并给出验证方式。
- 主动联系陌生潜在客户和邮件营销必须遵守目标市场的反垃圾邮件与隐私法规（如 CAN-SPAM、GDPR）及平台规则；联系人名单、受众导出数据保存在本地未跟踪文件，文档中只记录路径，不粘贴名单内容。
- 广告投放遵守各平台广告政策；每个 playbook 必须包含指标、判定标准和退出条件。
- 渠道实验按 `workflow/core/capabilities/channel-experiment-tracker.md` 口径登记。
- 默认使用简体中文展示工作流沟通和阶段产物；专有名词、产品名、品牌名、渠道名、代码标识符、命令、文件路径、API、SDK、框架、协议、标准和官方英文术语保留原文。
- 本阶段只产出执行方案和清单，不授权修改业务代码；landing page、博客、数据采集等需要改代码的营销需求，必须通过 `/new-feature` 作为一次新改动进入研发部分。
- 所有对外动作——发帖、投放、发送营销邮件、联系内容创作者或合作伙伴、提交目录站——需要用户明确授权或由用户自行执行；本阶段默认只生成待执行清单。

## Required Outputs

- Create or update workspace-level `business/{product}/B8-渠道执行策略.md`.
- Update workspace-level `business/{product}/00-商业化状态.md`.
- 输出营销工程需求清单（回流 `/new-feature`）和待授权对外动作清单。
- Record unvalidated assumptions and evidence gaps explicitly.

## Suggested Structure

1. **SEO playbook**：种子词 → 长尾关键词研究（含搜索意图分类）、内容日历、页面级 on-page 清单、技术 SEO 清单（sitemap、结构化数据、性能、移动适配）、外链策略、衡量口径（排名 / 自然流量 / 转化）。
2. **其他渠道 playbook**（每个 B6 选中渠道一节）：目标与漏斗位置、动作节奏（每周做什么）、素材需求、指标与判定标准、退出条件。
3. **实验设计**：本周期渠道实验清单——假设、预算上限、周期、判定指标、负责记录的位置。
4. **营销工程需求回流**：landing page、博客/文档站、埋点与分析、A/B 测试、分享机制等，逐项列出并标注对应 `/new-feature` 需求名。
5. **待授权对外动作清单**：发帖、投放、主动联系潜在客户、目录站提交等，逐项列出等待用户授权或自行执行。
