# /B9-策略复盘

## Goal

策略复盘: 按周期基于真实数据复盘漏斗表现、渠道 ROI 和假设判定，对每个渠道输出加码/保持/降配/砍掉的调整决策，并在重大失配时上溯修订定位与商业模式。

## Required Inputs

- `workflow/team-profile.yaml`
- Workspace-level `business/{product}/B5-渠道漏斗映射.md` 到 `B8-渠道执行策略.md`、渠道实验记录
- 漏斗与渠道真实数据（流量、转化、支出、时间投入）
- 上一轮 `B9-策略复盘.md`、相关 `features/{feature}/10-复盘总结.md` 的增长信号（如有）

## Execution Rules

- Read local facts before writing conclusions.
- 复盘必须基于真实数据快照；数据缺失时记录采集缺口和补齐方式，不得编造或用印象代替数据。
- 每个在投渠道必须给出明确处置决策（加码 / 保持 / 降配 / 砍掉）及理由；不允许全部"继续观察"。
- 常规偏差修订 `/B5` 到 `/B8`；重大失配（ICP 不对、付费假设证伪、定位不成立）必须上溯修订 `/B1`、`/B2` 或 `/B3`，并在状态文件标记。
- 建议节奏：每周检视指标、每月策略复盘、每季度校准定位；实际节奏写入状态文件。
- 默认使用简体中文展示工作流沟通和阶段产物；专有名词、产品名、品牌名、渠道名、代码标识符、命令、文件路径、API、SDK、框架、协议、标准和官方英文术语保留原文。
- 本阶段只产出复盘与调整文档，不授权修改业务代码；调整后的对外动作仍需用户授权或自行执行。

## Required Outputs

- Create or update workspace-level `business/{product}/B9-策略复盘.md`（按周期追加，保留历史结论）。
- Update workspace-level `business/{product}/00-商业化状态.md`（含本轮处置决策和下轮复盘时间）。
- Record data gaps, invalidated assumptions, and upstream revision needs explicitly.

## Suggested Structure

1. **数据快照**：周期区间、漏斗各层数据、各渠道流量/转化/支出、CAC 与 LTV 实际 vs 目标、时间投入实际 vs 预算。
2. **假设判定**：本周期验证 / 证伪 / 证据不足的假设清单，引用实验记录。
3. **渠道处置**：每渠道 加码 / 保持 / 降配 / 砍掉 + 理由 + 生效动作。
4. **上溯修订**：需要回改的上游文档（B1/B2/B3 或 B5-B8）与具体修订点。
5. **下一周期计划**：目标、预算调整、实验清单、待授权对外动作。
6. **经验沉淀**：可复用的渠道经验与教训，喂给 `/10-复盘总结` 和知识库。
