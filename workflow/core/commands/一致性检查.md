# /一致性检查

## Goal

开始修改前检查：在完整检查中，对同一改动的完成标准、产品说明、技术方案、测试和已上线功能说明做只读交叉检查。

## Required Inputs

- `workflow/policy.yaml`、`workflow/team-profile.yaml`、`workflow/constitution.md` 与 `workflow/standards/`
- `features/{feature}/00-完成合同.md` 和已有阶段文档
- `specs/` 已上线功能说明

## Execution Rules

- 轻量处理不要求单独运行本命令；完整 diff 审查会在实现过程中检查越界。
- **严格只读**：本命令不修改被检查的文档或业务代码。
- 检查以下内容：
  1. 同一事实在不同文档中是否互相矛盾；
  2. 每个目标是否有验收项，每个必须通过的验收项是否有来源和可重复方法；
  3. 完成标准的改动范围是否与技术方案、产品功能清单一致；
  4. 是否与项目基本规则和代码规范冲突；
  5. 要改的行为是否已对照 `specs/` 中的当前行为；
  6. 是否仍有待确认标记、无可观察定义的模糊词或占位符。
- 按“开始前必须解决 / 建议解决 / 可记录后继续”排序，每项引用文件与原文。无问题时明确说“未发现影响开始修改的不一致”。

## Required Outputs

- `features/{feature}/一致性检查.md`：检查范围、发现、位置、建议动作和结论。
- 更新 `features/{feature}/00-工作流状态.md` 中的开始前检查结果。
- 存在必须解决的问题时，指向可修正它的具体步骤。

## 内部兼容详情

技术详情可使用 `BLOCKER/MAJOR/MINOR`、`Oracle` 和 `blocking` 代码；默认用户输出使用上述中文表达。
