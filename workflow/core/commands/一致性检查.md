# /一致性检查

## Goal

一致性检查: 在进入实现（`/04-代码实现` 或 `/交付至完成`）之前，对同一需求的全部工件做只读交叉检查，逮住"PRD 说 A、架构写 B、测试测 C、合同定 D"式漂移，以及目标与 Oracle 的覆盖缺口。

## Required Inputs

- `AGENTS.md`
- `workflow/team-profile.yaml`
- `workflow/constitution.md` 与 `workflow/standards/`
- Workspace-level `features/{feature}/`：`00-完成合同.md`、`01`-`06` 各阶段文档
- Workspace-level `specs/` 现有行为基线
- 商业化基线（如存在）：`business/{product}/` 相关条目

## Execution Rules

- **严格只读**：本命令不修改任何被检查的工件，只输出检查报告；修复由用户确认后回到对应阶段命令执行。
- 检查维度：
  1. 冲突：同一事实在不同文档中的表述互相矛盾（口径、数值、范围、平台）。
  2. 覆盖：合同每条目标 ↔ 至少一条 Oracle；每条 blocking Oracle ↔ 可追溯的需求来源；`02B` 关键页面 ↔ 测试用例。
  3. 漂移：合同影响边界 vs `03-技术架构` 影响仓库清单；PRD 功能清单 vs 合同目标/非目标。
  4. 宪法冲突：任何工件与 `workflow/constitution.md` 原则、`workflow/standards/` 规范的直接冲突（constitution 在本检查范围内不可协商）。
  5. specs 冲突：合同将改变的行为是否与 `specs/` 现状对齐（brownfield 改动必须显式声明改变哪条现有行为）。
  6. 残留歧义：未清零的 `[待澄清]`、未绑定数字的模糊词、占位符「待填写」。
- 发现项按严重级别排序：BLOCKER（进入实现前必须解决）/ MAJOR（建议解决）/ MINOR（记录即可），每项引用具体文件与原文。
- 无发现时明确输出"未发现阻塞级不一致"，不得为了产出而编造问题。
- 默认使用简体中文展示工作流沟通和阶段产物；专有名词、代码标识符、命令、文件路径、API、SDK、框架和官方英文术语保留原文。
- This stage does not authorize business code changes.

## Required Outputs

- Create or update workspace-level `features/{feature}/一致性检查.md`：检查范围、发现清单（级别/位置/原文/建议修复动作）、结论。
- Update workspace-level `features/{feature}/00-工作流状态.md`（一致性结论与阻塞数）。
- 存在 BLOCKER 时明确建议先修复再实现；修复动作指向对应阶段命令。
