# /定义完成

## Goal

定义完成: 把 01-06 阶段的分散结论"编译"成一份可冻结、可机器判定的《完成合同》，通过 Definition Lint 后经用户确认冻结。合同是"什么叫完成"的唯一判定依据，也是 `/交付至完成` 与 `/04-代码实现` 的准入闸门。

## Required Inputs

- `AGENTS.md`
- `workflow/team-profile.yaml`
- `workflow/constitution.md`（不可协商原则）与 `workflow/standards/`（个人规范）
- Workspace-level `features/{feature}/` 下已有的 `01`-`06` 阶段文档（S 档至少需要 `01-需求讨论.md` 或等价的用户输入）
- Workspace-level `specs/` 现有行为基线（brownfield 时必读）
- 商业化基线（如存在）：`business/{product}/B2-商业模式.md`、`B5-渠道漏斗映射.md`

## Execution Rules

- Read local facts before writing conclusions.
- 本阶段是**编译**不是**发明**：合同内容必须能追溯到前序文档、specs、constitution 或用户的明确输入；发现前序文档缺失或互相矛盾时先补齐或对齐，不得临场编造填充。
- 按 `workflow/core/templates/completion-contract.md` 生成 `features/{feature}/00-完成合同.md`；复杂度 S 档只填 ★ 必填节，M/L 档全部填写。
- 每条目标必须被至少一条 Oracle 覆盖；每条 Oracle 必须绑定可复现验证方法（auto 优先，manual 必须带步骤和判定标准）；blocking Oracle 至少一条。
- 验收标准使用 EARS（WHEN/WHILE/IF…THEN/WHERE + SHALL）或 Given/When/Then 句式；出现模糊词（快、流畅、稳定、好用、优雅、高性能、健壮、无缝、及时、大量）必须绑定数字或可观察行为，否则写入待澄清项。
- 冻结前必须执行 Definition Lint（按 `workflow/core/capabilities/definition-lint.md` 逐维检查并把结果写入合同 Lint 表）；未通过项要么补齐，要么经用户确认后记为豁免并说明风险。
- 冻结前待澄清项必须清零：逐条解决，或经用户确认降级为「已记录假设」。可先运行 `/澄清` 收敛。
- 如果 kit 提供了 `bin/check-contract.cjs`，冻结前运行 `node <kit>/bin/check-contract.cjs features/{feature}/00-完成合同.md` 做结构校验并记录结果。
- **冻结需要用户明确确认**；agent 不得自行冻结合同，也不得在冻结后静默修改标准——修改走「修订记录」并再次经用户确认。
- 默认使用简体中文展示工作流沟通和阶段产物；专有名词、产品名、品牌名、代码标识符、命令、文件路径、分支名、API、SDK、框架、协议、标准、错误信息和官方英文术语保留原文。
- This stage does not authorize business code changes.

## Required Outputs

- Create or update workspace-level `features/{feature}/00-完成合同.md`（含 Lint 结果表和结构校验结果）。
- Update workspace-level `features/{feature}/00-工作流状态.md`（复杂度档位、合同状态、Lint 状态、Oracle 汇总）。
- 向用户呈现：合同摘要、blocking Oracle 清单、Lint 未过项与豁免请求、待确认的冻结请求。
- Record unresolved questions and evidence gaps explicitly.

## 冻结后的效力

- `/04-代码实现`、`/04A`、`/04B`、`/交付至完成` 的准入条件之一是本合同「已冻结」且 Lint 通过（S 档要求 ★ 节完整）。
- `/05-代码审查` 以合同影响边界为范围漂移基准；`/07-测试执行` 只能翻转 Oracle 状态并附证据。
- `/08-发布准备` 的发布准入 = blocking Oracle 全 PASS（或 WAIVED 且有用户确认记录）。
