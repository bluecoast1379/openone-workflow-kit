# /定义完成

## Goal

确认完成标准：把目标、改动范围、风险与验收方法整理成一份可执行的标准，用于完整检查。

## Required Inputs

- `workflow/policy.yaml`、`workflow/team-profile.yaml`
- 项目基本规则 `workflow/constitution.md` 与代码规范 `workflow/standards/`
- `features/{feature}/` 下已有的需求、产品、UI、架构和测试结论
- 已上线功能说明 `specs/`

## Execution Rules

- 本命令是“完整检查”的准备步骤。轻量处理不要求单独运行它；用户主动要求整理完成标准时除外。
- 只整理已有事实和用户明确输入，不自行发明缺失的业务规则。冲突或缺失会影响结果时，输出具体待确认项。
- 使用 `workflow/core/templates/completion-contract.md` 生成 `features/{feature}/00-完成合同.md`。文件名为兼容保留，默认对用户称为“完成标准”。
- 每个目标至少有一个验收项；验收项必须包含可重复的命令，或带步骤和判定标准的人工检查。至少有一项标为“必须通过”。
- 验收表述应绑定数字或可观察行为；“快、稳定、好用、流畅”等词不能单独作为标准。
- 按 `workflow/core/capabilities/definition-lint.md` 运行“完成标准检查”。如果 kit 提供 `bin/check-contract.cjs`，同时运行结构检查。未通过项要么补齐，要么由用户明确确认跳过并记录风险。
- 待确认项必须在确认完成标准前清零，或由用户确认为已记录假设。
- **完成标准需要用户明确确认。** agent 不得自行代替用户确认；确认后不得静默改标准、阈值或必须通过标记。
- 本步骤不授权修改业务代码。

## Required Outputs

- `features/{feature}/00-完成合同.md`（默认展示名：完成标准）。
- `features/{feature}/00-工作流状态.md` 中的完成标准状态、检查结果、必须通过的验收项进度。
- 给用户的默认输出只包含：目标、范围、必须通过的验收项、未通过的完成标准检查、需要用户确认跳过的项。

## 确认后的效力

- 完整检查中，`/04`、`/04A`、`/04B` 和 `/交付至完成` 要求完成标准已确认且检查通过。
- `/05-代码审查` 用其中的改动范围判断是否越界；`/07-测试执行` 只更新验收结果和证据。
- `/08-发布准备` 要求所有必须通过的验收项已通过，或已由用户确认跳过并记录风险。

## 内部兼容详情

旧名“完成合同/冻结/Definition Lint/Oracle/blocking”仅供文件名、校验器与审计兼容。默认对用户显示“完成标准/已确认/完成标准检查/验收项/必须通过”。
