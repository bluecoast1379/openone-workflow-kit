# /澄清

## Goal

澄清: 用不超过 5 个高针对性问题消融需求中的语义歧义，把答案直接写回阶段文档，并清理 `[待澄清: …]` 标记。可在 `/01-需求讨论`、`/02-产品文档` 期间或 `/定义完成` 冻结前随时调用。

## Required Inputs

- `AGENTS.md`
- `workflow/team-profile.yaml`
- `workflow/constitution.md`（已有原则不再重复提问）
- Workspace-level `features/{feature}/` 下的现有阶段文档
- Workspace-level `specs/` 现有行为基线（已实现行为不再当新问题问）

## Execution Rules

- 每轮最多 5 个问题，按「对完成定义的影响 × 当前不确定度」排序，只问真正改变结论的问题；能从本地文档、代码、specs 或 constitution 推出的答案不要问用户。
- 每个问题给出建议默认值和 2-3 个候选选项，让用户可以快速选择而不是写作文。
- 答案必须写回对应文档的对应章节，并同步更新术语表；不允许答案只留在聊天记录里。
- 发现模糊词（快、流畅、稳定、好用、优雅、高性能、健壮、无缝、及时、大量、尽快）时，必须请用户绑定数字或可观察行为，或由 agent 提议绑定值请用户确认。
- 无法当场解决的问题，用 `[待澄清: 问题描述]` 标记写入文档相应位置；`/定义完成` 冻结前必须清零。
- 验收相关的澄清结果建议改写为 EARS 句式（WHEN/WHILE/IF…THEN/WHERE + SHALL）或 Given/When/Then，直接可作 Oracle 候选。
- 用户明确表示跳过澄清（如探索性 spike）时可以继续后续阶段，但必须警告下游返工风险并在状态文件记录。
- 默认使用简体中文展示工作流沟通和阶段产物；专有名词、代码标识符、命令、文件路径、API、SDK、框架和官方英文术语保留原文。
- This stage does not authorize business code changes.

## Required Outputs

- 更新对应的 `features/{feature}/` 阶段文档：答案入正文、术语入术语表、未决项入 `[待澄清]` 标记。
- Update workspace-level `features/{feature}/00-工作流状态.md`（剩余待澄清项数量）。
- 向用户输出本轮问题清单、已消融项和剩余风险。
