# 工作区宪法（constitution）

> 本文件存放**跨需求不可协商的原则**——每个需求不再重复讨论的既定决策。事实与路径配置放 `workflow/team-profile.yaml`，可复用代码规范放 `workflow/standards/`；本文件只放原则。
> 效力：`/定义完成`、`/一致性检查`、`/04-代码实现`、`/05-代码审查`、`/交付至完成` 都以本文件为不可协商基准；与本文件冲突的需求必须先修订宪法（经用户确认并记录），不得静默绕过。
> 每条原则写三段：原则 / 为什么 / 例外条件（没有例外就写"无"）。

## 技术栈与依赖

- 原则：待填写（例：默认 TypeScript + 最小依赖；新增运行时依赖每需求 ≤2 个）
- 为什么：待填写
- 例外条件：待填写

## 安全与隐私底线

- 原则：待填写（例：凭证只放本地未跟踪文件；不收集非必需个人数据；输入一律校验）
- 为什么：待填写
- 例外条件：无

## 质量与测试底线

- 原则：待填写（例：blocking Oracle 未全绿不发布；核心路径必须有 auto Oracle）
- 为什么：待填写
- 例外条件：待填写

## UX 底线

- 原则：待填写（例：每个页面必须定义空/错/载三态；错误信息必须可行动）
- 为什么：待填写
- 例外条件：待填写（例：内部工具可豁免动效规范）

## 成本上限

- 原则：待填写（例：单项目月固定成本 ≤ $X；引入付费服务需用户确认）
- 为什么：待填写
- 例外条件：待填写

## 发布纪律

- 原则：待填写（例：`prod` 只接受来自 `main` 的提升；发布必须有回滚点）
- 为什么：待填写
- 例外条件：待填写

## 永不做清单

- 待填写（例：不做需要收集通讯录的功能；不接入需要独占锁定的平台）
