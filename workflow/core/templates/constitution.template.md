# 项目基本规则

> 本文件存放**所有改动都必须遵守的原则**——每次不再重复讨论的既定决策。事实与路径配置放 `workflow/team-profile.yaml`，可复用代码规范放 `workflow/standards/`；本文件只放原则。
> 与本文件冲突的改动必须先由用户确认修订基本规则，不得静默绕过。
> 每条原则写三段：原则 / 为什么 / 例外条件（没有例外就写"无"）。

## 技术栈与依赖

- 原则：待填写（例：默认 TypeScript + 最小依赖；新增运行时依赖每需求 ≤2 个）
- 为什么：待填写
- 例外条件：待填写

## 安全与隐私底线

- 原则：待填写（例：凭证只放本地未跟踪文件；不收集非必需个人数据；输入一律校验）
- 为什么：待填写
- 例外条件：无

## 质量与测试底线

- 原则：待填写（例：必须通过的验收项未全部通过时不发布；核心路径必须有自动检查）
- 为什么：待填写
- 例外条件：待填写

## UX 底线

- 原则：待填写（例：每个页面必须定义空/错/载三态；错误信息必须可行动）
- 为什么：待填写
- 例外条件：待填写（例：内部工具可豁免动效规范）

## 成本上限

- 原则：待填写（例：单项目月固定成本 ≤ $X；引入付费服务需用户确认）
- 为什么：待填写
- 例外条件：待填写

## 发布纪律

- 原则：待填写（例：发布按仓库已配置的分支流程执行；发布必须有回滚点；分支角色未知时先补配置）
- 为什么：待填写
- 例外条件：待填写

## 永不做清单

- 待填写（例：不做需要收集通讯录的功能；不接入需要独占锁定的平台）
